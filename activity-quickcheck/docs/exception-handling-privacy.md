# 活动速签：匿名常态与扫码异常人工兜底

状态：`test/activity-live-sandbox` 开发中；2026-10-14。仅限虚构数据，不表示校园真实学生认证或学校正式票务服务。Cloudflare D1 实现已添加，暂未部署，校园 Node/SQLite MVP 也尚未同步本变更。

## 原则和角色

常态下，签到工作人员只获得核销成功或失败结果，不获得姓名、学号、材料或可跨平台关联的身份编码。二维码 `bqx_<64 个十六进制字符>` 仍是 256 位随机、约 45 秒有效、一次性使用的服务端核销凭证。

| 身份 / 岗位 | 常态可见 | 有条件获得的身份数据 |
| --- | --- | --- |
| 学生 | 自己的报名状态、随机人工编号、动态 QR | 自己的姓名/学号，不代表已校方认证 |
| 扫码员 scanner | 本场活动计数、扫码成功/失败 | **无**；不可调用异常身份查询、附件接口、导出 |
| 审核员 reviewer | 匿名报名标识、审核状态、授权的证明附件 | 常态 API 不返回姓名/学号；附件内容本身可能含个人信息，必须单独治理 |
| 人工窗口 manual | 本场活动匿名计数 | 仅在学生本人现场主动请求协助、填写原因和说明并通过限流后，可一次查询单个编号对应的自填姓名/学号 |
| 活动负责人 owner | 匿名队列、岗位分配 | 可经审计的单人异常查询；正式申报的最小必要 CSV 导出也留审计记录 |

正常扫码成功 `200 {ok:true}` 不包含学生身份；后台也不再为普通队列 JOIN 学生身份表。人工窗口不再提供按姓名或学号的整表搜索。

## 双线索冗余

1. **动态 QR**：学生出示的仍是不可读的 `bqx_...` 随机令牌。后台只保存 SHA-256 摘要。每次签发时，将摘要与报名、事件、签发/过期时间写入受权限保护的 `activity_ticket_history`。即使后来生成新 QR、旧码过期或已经完成签到，授权人工窗口仍可在 **过期后 48 小时内** 根据曾真实解出的完整码值做异常回查。回查不会重新使码有效、不会自动产生签到记录。
2. **独立人工编号**：每次报名生成 `BM-XXXX-XXXX-XXXX`（Crockford Base32，12 字符约 60 位随机熵，事件内唯一）。编号只随机生成，不包含姓名、学号或报名 UUID。它显示在学生本人的报名/二维码页面，二维码失焦、屏幕破裂、相机或网络故障时可以口述；容忍常见的 O/0、I/L/1 抄录混淆。编号不用于登录、核销或学生认证。服务端只有确认学生自己已登录才显示其编号。

## 异常处理（必须在线、必须单条）

1. 学生确认无法正常扫码；优先尝试刷新正常二维码。仍失败时去独立人工窗口，主动提供 BM 编号或完整有效/过期的活动二维码码值。
2. 仅本活动的 manual 或 owner 可以调用 `POST /api/events/:id/assist-lookup`。参数为 `reference`、`reasonCode`、至少 8 字的 `reasonNote`、`studentPresent:true`。服务端按工作人员+活动限流，验证岗位、事件范围和编号格式；不能跨事件查询。
3. 服务端写入 `activity_exception_lookup` 审计记录（工作人员、事件、匹配到的报名 ID、QR/编号类型、原因、说明、结果、时间），**不记入姓名、学号或二维码/人工编号原文**；没有命中也记审计。
4. 有效命中才返回这一条报名的自填姓名、自填学号、材料审核状态及此前到场状态。窗口工作人员须结合现场出示的独立证明面对面核对。自填学号不等于学校官方认证。
5. 本场扫码或人工到场已记录的，明确提示“已到场”，**不得再次核销**。无到场记录时，工作人员再勾选已当面核实，方可按现有单一数据库唯一约束登记人工到场。manual 岗位在过去 10 分钟内必须有本人针对同一报名的一次成功、带原因的异常查询；活动负责人仍可执行受审计的特殊处理。
6. 人工到场不代表资料审核通过；只有 **已审核且已到场** 的申报候选名单才可由活动负责人导出。查询界面在人工登记后清空本次个人信息。

## 失败场景和处置边界

- 摄像头被占用、权限被拒、无法识码：尝试恢复相机；失败走 BM 编号与人工窗口。
- QR 过期、重放、已经核销：普通扫码不给个人信息；已签到则只报告“已到场”，不得再次写入。过期 QR 摘要只供被授权的异常查询。
- 审核还未通过或集赞截图仍在补交：允许经严格现场核实的人工到场，不会自动批准材料。
- 学生没有可展示编号、手机无电、无法登录：不能依赖猜测姓名/学号查全表。升级负责人独立核实；正式业务需要双人复核与书面留痕，当前不应绕过身份治理。
- 整体网络离线：人工登记先记为“待回传纸质/离线待核实”，**不是已正式签到**。网络恢复后只向唯一权威库执行一次受审计登记；不得创建独立的第二个签到写入源。
- 错误的校方支付二维码、陌生 URL：不解码成学号，不用作身份查询，直接拒绝。

## 隐私、安全与部署前清单

- 升级前先在**隔离测试 D1** 应用 `cloudflare-live/migrations/0003_manual_exception_lookup.sql`。历史报名数据不丢失；学生下一次认证查看报名时会补充人工编号。
- QR 摘要回查在 SQL 上有 48 小时窗口。服务端提供 `scheduled()` 清理处理器，但**必须在部署时配置 Wrangler Cron Trigger**（例如每小时）才保证后台定期物理清理。当前代码不代表已部署定时清理。
- 启用 `ASSIST_RATE_LIMIT`，或者复用现有 `AUTH_RATE_LIMIT`（服务端已做后备）；真实试点须独立调校限制、监测查询异常和定期审阅 `activity_exception_lookup`。
- 审计说明不应填写身份证号、真实截图内容等额外敏感信息。真实数据上线前必须确认数据留存/删除与权限访问政策，并改为个人专属工作人员账号（不能沿用公开共享演练密码）。
- **当前不提供校方可信实名、正式活动票导入或线下断网核销**。需要学校授权的身份认证/官方流程及独立安全验收，才可开展真实学生试点。
- 本更改只更新了 Cloudflare 活动服务工作区；本地 `server.mjs` 的旧版人工搜索和扫描权限尚未同步，不可视作具备同等隐私保障。


## 2026-10-14 · Material 3 人工窗口及 USB 真机联调

本轮新增 `public/material3.css`：使用 Material 3 配色角色（primary、surface、secondary-container、error/success）、大型圆角卡片、填充文本框、圆形按钮、匿名工作台和“① 查找线索 → ② 当面核对 → ③ 记录到场”的步骤提示。没有依赖 Google Fonts、CDN 或第三方云字体。原有全屏扫码层使用独立 `scanner.css`。

个人信息仅在人工窗口的单次授权查询成功后写入页面；**60 秒后、页面进入后台或离开工作台时自动清除**。成功登记后，人工编号、说明与身份也从当前工作台清空。扫码员依旧无法获得姓名/学号。客户端可见性清理是额外防护，不能代替服务端岗位权限与审计。

### 可重复执行的 USB 虚构数据联调

在 Ubuntu 活动目录运行：

```bash
npm ci
npm run qa:phone
```

该命令启动本机临时 HTTP 服务 `127.0.0.1:3318`，模拟 Cloudflare D1 绑定（SQLite 内存数据库）；**实际调用同目录 `cloudflare-live/worker.mjs`** 处理报名、出票、核销、人工查询、审计和到场写入。运行前会在内存里按三份 SQL 迁移新建库，仅插入 `TEST-USB` 虚构学生账号、虚构活动和独立工作人员账号。程序退出数据消失。

连接 Android 调试手机，确保已构建并安装包含 Debug QA 入口的花工木棉 Beta：

```bash
adb reverse tcp:3318 tcp:3318
adb shell am start -n cn.scut.bombax.beta/cn.scut.bombax.activity.ActivityPortalActivity --es bombax.activity.destination qa
```

只能在 Debug 包通过上述入口访问本机服务。Release 不导出活动 Activity，且不允许 localhost HTTP。Debug 的允许域名仍限于 `127.0.0.1:3318`，不打开校园网服务器端口。

手机上方有 **“USB 实机 QA · 仅虚构数据”** 的角色切换入口（脚本仅由本地 QA 服务器插入，生产资产不包含）。先用扫码员进入全屏扫码；真实摄像头开启之后，调试钩子会**仅注入一次过期二维码的解码回调**。这是扫码失败流程演练，不是实物光学识码验收。随后以学生角色进入报名页查看自己的随机 `BM` 备用编号，再切回人工窗口填写“二维码已过期或已使用”的原因和现场说明、确认学生在场，查询单条报名；最后勾选独立现场身份核验、人工登记到场。

从 Ubuntu 查询纯虚构测试结果：

```bash
curl -sS http://127.0.0.1:3318/__qa/state
```

2026-10-14 实测：Android 14 手机真实摄像头连通；过期码得到服务器拒绝且签到为 0；人工查询恰好产生日志 `expired_qr, matched=1`；手机点“确认登记人工到场”后，临时数据库新增 1 条 `manual` 记录，页面不再显示 `测试学生甲` 或 `TEST-USB-001`。前端 Material 3 交互也经 Chromium 真实 Worker 本地端到端自动化验证。此联调**不触碰学校正式数据，不意味着已集成可信校方认证或官方活动票接口**。

### 上线前仍需

Cloudflare 正式测试站应用 D1 迁移 `0003_manual_exception_lookup.sql`、配置 `ASSIST_RATE_LIMIT` 和带调度的 QR 摘要清理，再在专属人员账号下做鉴权和安全测试；目前这些都是**未部署**更改。普通旧版 `server.mjs` 使用不同的数据模型，尚未统一到本次匿名 + 异常查询机制，因此正式活动端应基于 Cloudflare Worker 而非旧版演示服务。

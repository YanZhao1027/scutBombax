# 一码通：学生免登录、一个固定二维码贯穿全活动（2026-10-17）

> 本分支是**仅使用虚构资料的 Cloudflare Stage 开发方案**，未部署、未执行线上 D1 迁移。不同于仓库内仍维持账号制的旧 Node/SQLite 本地 MVP。主办方、审核员、扫码员、人工通道必须登录并按活动岗位授权，学生无需注册与登录。

## 流程

1. 学生无需登录，即可浏览活动、填写**虚构**姓名（“测试”开头）和**虚构**学号（`TEST-` 前缀）、确认演练告知并提交报名。
2. 服务端为本次报名生成**唯一固定、随机的 256 位一码通**，格式为 `bqx_` 加 64 位小写十六进制。D1 中 `activity_guest_access.token_digest` 仅保留其 SHA-256 摘要，绝不存放明文，也不嵌入姓名/学号。服务端通过摘要查询对应报名，**无需加密个人信息再放入二维码**。
3. 页面立即显示一码通二维码，可下载或截图妥善保存；二维码包含 HTTPS 地址和 `#pass=bqx_...` **URL 片段**（不是查询参数）。片段不会随页面请求发给服务器；同源脚本读取后通过带同源防护的 `POST /api/pass/restore` 验证，**立刻从浏览器地址栏/历史中清除片段**，并签发本次活动专属的 `HttpOnly; Secure; SameSite=Strict; Path=/api` Cookie。QR 原码仍是整个活动的固定凭证。
4. 在原浏览器或换设备扫描**同一个二维码**，即可查询“审核中 / 不可签到”“审核通过 / 可签到”或“已签到”，也能提交允许的模拟材料。二维码在工作人员核销后**不会销毁或轮换**，仍然可查状态。
5. 已登录且被授权的**扫码员/活动负责人**，在活动开始与结束时间之间读取**同一个二维码**，先当面核对持码学生身份。服务端检查活动、审核状态和凭证有效期，然后靠 `activity_attendance.registration_id` 唯一约束完成**至多一次成功核销**。审核员及匿名游客不能核销。
6. 原 `/api/events/:id/ticket`、`/api/qr` 的 45 秒动态码路径已停止使用（返回 HTTP 410）；`/api/events/:id/pass-qr` 根据本次活动的安全 Cookie 反复显示**同一个二维码**。历史 `activity_tickets` 表不删除，仅新流程不使用。

## 安全边界

- **一码通是 bearer capability（持码即拥有查看/补交本人报名资料的权限）**。它不可从学号、姓名、报名 UUID 推测；但任何复制到二维码照片的人都可能使用。**仅加密二维码并不能阻止转发冒用**；工作人员必须现场核对，不能依赖静态码判定真实身份。这是“一码使用到底”与强防代签间的真实权衡。
- 只有服务器能查询此码对应哪份报名。扫描页面时不把 QR 令牌写入 HTTP URL 查询参数、日志、R2、CSV 或本地存储；前端只短暂解析片段，随后清除。原浏览器使用 `HttpOnly` Cookie 会话，取回二维码也需要有效 Cookie。
- 单码仅属于**一个活动的一次报名**；跨活动、跨学生凭证不允许访问材料/修改/核销。原有测试数据范围门禁 `SYNTHETIC_ONLY=true` 且 `ENABLE_LIVE=true`、同源写操作验证、Cloudflare IP 限流、岗位授权及 D1 签到唯一约束仍强制有效。
- **不要求学生在现场再次开 GPS 生成码**。场地有效性由已授权现场工作人员核实；这不是可被服务端独立证明的学生 GPS 定位。若未来要严格防远程代签，需另设计学校身份核验或设备绑定，不能不加说明就称之为防作弊通过。
- 此虚构 Stage 的一码通**不换码，有效至活动结束后 30 天**（用于状态查询，暂定的测试保留期限，不代表任何真实学生数据留存许可）。之后失效但原报名数据不会自动删除；**真实数据删除、遗失挂失、撤销重发、工作人员复核及并发压测仍必须在生产前完成**。
- `POST /api/pass/restore` 强制 IP 限流和同源写入校验；学生没有工作人员登录凭证，不能访问审核队列、分配岗位或导出 CSV。后台测试站禁止调用第三方 AI 处理材料。
- 二维码若丢失，且原浏览器 Cookie 也已失效，**无法仅凭自填学号在线找回**；目前没有自助恢复、重发或挂失端点，正式环境上线前必须解决。

# 学生免登录 · 仅虚构数据 Stage 设计（2026-10-17）

本分支为**独立测试提案，不部署、不收集真实学生数据**。产品决定是：**学生无需创建账号或登录；主办方、审核员、扫码员、人工签到员必须使用主办方账号登录并按活动授权**。

## 学生流程

1. 免登录查看活动列表，选择活动，填写**虚构**姓名（“测试”开头）和**虚构**学号（“TEST-”开头），明确勾选演练告知后报名。服务器不接受真实学号及照片。
2. 后端使用不可预测的 256-bit 随机凭证，D1 **只保存 SHA-256 摘要**，原始凭证只写入 `HttpOnly; Secure; SameSite=Strict; Path=/api` 浏览器 Cookie（**每个活动一个不同名称**）。前端 JS 不能读取它，URL、动态签到二维码、CSV、R2 均不承载该凭证。
3. 用户在**同一浏览器**再次进入该活动时，可读取**自己的**审核状态、上传**内置模拟图片**、生成本人 45 秒有效的活动二维码。不能传入学号、姓名或其它报名编号以获取他人资料。
4. 浏览器 Cookie 丢失、凭证过期或换设备后，**不能仅凭自填学号/姓名在线找回**。当前版本仅保留主办方现场人工协助的产品方向，**自动找回/重新签发尚未实现**。凭证最长 30 天且不晚于活动结束 7 天后；若活动预定时间较远，凭证可能在活动开始前失效，正式版本须完善时效策略。
5. 曾使用密码注册的历史学生账号不再允许学生登录；历史记录仍可由有权限的工作人员查看。主办方用户名和密码必须由安全渠道独立配置，公开学生报名接口不能授予任何工作人员身份。

## 最小权限与失效保护

- 匿名提交报名会经过原有同源写请求校验、`AUTH_RATE_LIMIT` 强制频率限制、Cloudflare 来源检查和 `SYNTHETIC_ONLY=true` / `ENABLE_LIVE=true` 总门禁。未配置限流则拒绝。
- 一场活动只能凭**该活动的 Cookie**操作该活动的报名；其它活动 Cookie 不可互换。工作人员单独登录，并在每次读材料、审核、导出或核销时验证岗位。
- 本次沿用活动报名表与图片、短时 QR、签到唯一性约束；匿名登记会为数据库关系完整性创建**无法登录的内部占位学生记录**，原样保存用户自填的虚构学号于受保护的 `activity_guest_access`。学生不能成为 organizer。
- 图片读取要求同一报名凭证，或活动 owner/reviewer 岗位；匿名不能读取审核队列、人员授权和 CSV。二维码即使被分享也不能被他人用来再次生成图像（但**实物截图仍可能被他人代扫**，须现场人工核验）。
- 测试站禁用付费 DeepSeek 调用，不应展示 AI 同意选项。学校身份、同意告知、留存/删除、照片 EXIF 清理、隐私与现场并发测试仍不完善，**禁止切换为真实学生生产模式**。
- 不设置学生通用密码，不自动生成可公开猜测的凭证，也不对外开放凭学号重置 Cookie 的接口。

## D1 迁移（仅在人工审核后于隔离 Stage 执行）

按照已存在的顺序先执行 `migrations/0001_init.sql`、`migrations/0002_password_iterations.sql`，再执行新增的 `migrations/0003_guest_access.sql`。只新增表与索引、不重建或删除已有活动、报名、人员权限与签到记录。**本轮未运行线上 Wrangler 迁移或部署**；部署前需核对目标 Stage 绑定，测试数据备份，先完成独立登录和兼容回归。

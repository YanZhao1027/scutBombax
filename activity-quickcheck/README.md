# 花工木棉 · 活动速签 — 独立 MVP

**当前仅供 Ubuntu 本机开发和虚构数据测试，未公开部署，未经学校官方身份认证。**

本模块独立于 Android、鸿蒙、iOS 一卡通客户端，功能为：
学生账号注册及报名 → 附件上传 → 活动主办方审核 → 现场浏览器定位 → 45 秒一次性二维码 → 工作人员扫码核销 → CSV 名单导出。

## Ubuntu 使用方法

要求 Node.js 22.13+、npm：

    cd activity-quickcheck
    npm ci
    npm test
    npm run bootstrap
    npm start

在 Ubuntu 本机浏览器打开 http://127.0.0.1:3317 。

首次运行的 bootstrap 会在 Ubuntu 终端交互式创建主办方账号（>=12 位密码）；不要在聊天、命令行参数、Git 中传递真实密码。可重复运行来创建第二、第三名核验员，活动创建者再通过活动后台授予其该活动核销权限。

先只用虚构姓名、学号和图片测试。请勿将本项目直接部署公网或收集真实学生资料。后台当前只监听 127.0.0.1，不会自动开放外部访问。若将来需要公网部署，应接入 HTTPS 反向代理、审核生产安全设置并设置 ACTIVITY_PUBLIC_ORIGIN；反向代理正确配置以后设置 ACTIVITY_TRUST_PROXY_HTTPS=1 以启用 Secure Cookie。普通 HTTP 的远程设备网页不能正常请求相机和地理定位。

## MVP 功能

1. 主办方新建活动：地点 WGS84 经纬度、定位半径 50–1000 米、签到起止日期、是否必须上传附件。
2. 学生使用独立账号报名，自填姓名和学号（**不等于官方校方实名**），最多传三份 PNG/JPEG/PDF，单份最多 3 MiB。
3. 主办方审核材料；补充上传会重置审核状态；审核意见可反馈学生。
4. 学生审核通过、在签到时间内，主动授权浏览器定位；原始位置仅作当次服务器判断，不保存精确位置。GPS 精度要求不大于 120 米。
5. 随机 256 位签到码、45 秒后过期；二维码不包含姓名、学号、会话凭证或支付码。
6. 授权的活动核验员扫码或手工录入码；SQLite 事务 + 唯一键保证多窗口仅有一次成功核销。
7. 仅导出审核通过且已现场核销者的 CSV（Excel 可读，做了表格公式注入防护），供主办方按官方要求整理提交。

## 隐私与安全边界

- 活动系统与一卡通账号密码、Cookie、令牌、学校官方认证码、微信身份完全隔离。
- 学生学号目前属于自填字段，无法有效防止冒用身份；GPS 可以模拟，不能把定位当成严格防作弊手段。
- 所有附件存放在 var/uploads 私有目录，随机文件名、0600 权限；通过登录鉴权才能查看。
- session token 仅在 SQLite 中留 SHA-256 摘要；登录 12 小时过期。二维码只留 token 摘要，用后即失效。
- 最终导出的是主办方申报候选名单，不代表学校发放了活动票。
- 这是 MVP，仍缺少：用户信息自主删除/更正、数据留存期限、图片 EXIF 去除、恶意文件扫描、完整安全审计、官方 Excel 模板适配、室内定位人工复核页面以及真实 500 人压测。
- 正式上线必须先补齐隐私告知、留存/删除治理、授权和 HTTPS 配置。不允许将本地测试当作上线验收。

## 工程

- server.mjs：Node 原生 HTTP API 与扫码事务逻辑
- db.mjs：SQLite 数据库、scrypt 散列、CSV 安全
- public/：移动端学生和主办方网页，摄像头扫码使用本地打包 ZXing
- scripts/bootstrap.mjs：本地主办方初始化
- tests/flow.test.mjs：自动化端到端权限和重复核销测试

## 接受标准

npm test 通过只证明自动化 HTTP 场景，不表示已完成真机测试、生产环境验收或实时三秒核销验证。三通道 500 人 8 分 20 秒仅是理论值；下一阶段须 50 人现场试点和真实并发性能测试。

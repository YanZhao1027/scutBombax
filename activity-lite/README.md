# 花工木棉 · 活动速签 Lite（学生无账号，活动方分权）

**开发状态：本地原型；未部署、未接入正式学校系统。** 2026-10-14。

## 产品分工

- **学生浏览器网页（无登录）**：提交必要信息和最多一张 2MB 图片材料，得到随机私密回执链接。手动打开并刷新审核结果；通过后在浏览器 Canvas 中生成签到二维码。回执链接不包含在签到码中，不向服务器上传二维码图片。
- **活动方网页审批后台（需账号）**：活动管理员创建活动、分配子账号及权限；材料审核员查看材料、批准/驳回；有导出权限者下载“审核通过且到场”的 CSV；有异常人工登记权限者核验后补登。
- **花工木棉 Android App（最终现场入口）**：工作人员使用独立活动方账号登录，启动 App 内全屏摄像头扫码。扫码只向 Lite Worker 发 HTTP POST，一次原子核销后显示绿/红状态，**绝不返回学生姓名、学号、联系方式**。
- **Web 可临时扫码测试**：`/#scan=<活动ID>` 提供扫码人员权限验证与全屏浏览器相机供调试。网页测试通过后，再完成 App 内原生扫码体验。现有 Android Beta 的旧活动入口**尚未切换到 Lite**。

整个 Lite 不需要学生账号、学生 GPS、地图、WebSocket、推送或宿舍公网服务器。

## 每场活动自己的管理员与子账号

创建活动需要部署环境中的高熵 `LITE_ROOT_TOKEN`，创建者同时输入初始管理员**用户名、显示名称和至少 12 位密码**。活动管理员凭账号登录（服务端保存 PBKDF2-SHA256 加盐哈希，21 万次迭代），后台通过带 `HttpOnly`、`SameSite=Strict`、HTTPS `Secure` 的 Cookie 维持约 12 小时会话。

每个活动的用户名独立，同名账号在别的活动不共享身份、密码或权限。管理员在后台可创建**普通子账号**、授予以下四项布尔权限、撤销权限、停用/启用账号及重置密码：

| 授权项 | 可以做 | 不能做 |
| --- | --- | --- |
| `review` 材料审核 | 查看本活动报名信息与私有材料，提交审核结论 | 创建员工账号、核销、导出（除非另有授权） |
| `scan` 现场扫码 | 仅使用扫码 API 返回成功/失败 | 查名单、学号、联系方式、材料、导出、管理员设置 |
| `export` 名单导出 | 导出已审核且到场的最小必要名单 | 查看完整审核队列、扫码、修改账号 |
| `manual` 异常人工登记 | 查看本活动待处理记录，并在当面查验后记到场 | 审核材料、导出、创建账号（除非另有授权） |

管理员隐含全部权限，只有管理员可以管理子账号；子账号无法创建管理员或提升自身权限。**任何子账号修改都会撤销该账号所有当前会话**。禁用账号、权限变更、重新登录、审核、人工签到、CSV 导出均有对应数据库字段或审计记录。扫码签到将具体工作人员 ID 写入到场记录。

**当前这是“每活动独立账号”，不是跨社团或跨活动的全局组织账号。** 如果未来管理员要统一管理十几场活动，再评估是否引入组织级身份管理；不能为一场活动的需求提前做成全校通用系统。

## 为什么学生仍无需身份认证

学生保存随机 `#receipt=<64 位 hex>` 回执，服务器只保存 SHA-256 摘要；审核通过后从 `/api/receipt/ticket` 签发另一枚随机 `#checkin=<64 位 hex>` 一次性票据。前端打包的 `qrcode` 本地绘制 Canvas，ZXing 在工作人员设备解码；服务端只核销**完整、所属活动、审核通过且未到场**的票据，并禁止重复签到。URL `#...` fragment 不在默认 HTTP 请求中直接发送，但仍是**持有即有权限的链接**，不能转发私密回执给陌生人。

二维码被截图转发仍可能导致代签。每场活动只有受权工作人员能核销，但 Lite **没有官方学籍认证，也不保证排除代签到**；必要时应当面核对，不应把自填学号当作官方身份凭据。

## 云端/宿舍网络

静态网页从 Cloudflare Assets 提供，少量 JSON 请求由 Worker 处理，报名数据库和权限审计保存在独立 D1，上传截图在私有 R2。**不需要宿舍 5 MB 上行服务，也没有实时推送**。学生查看反馈需主动刷新；工作人员扫码单次请求服务器。

## Ubuntu 本地测试（只允许虚构数据）

```bash
cd /home/zyubuntu/scutbombax/scutBombax-activity-live/activity-lite
npm run build:qr
npm test
npm run dev:local
```

本地服务只绑定 `127.0.0.1:3319`，通过隔离内存 SQLite + 虚构 R2 跑**真实 Worker 业务逻辑**。浏览器打开 `http://127.0.0.1:3319`。本机特有的 `/__qa/context` 返回**临时虚构活动的**报名入口、活动方登录入口以及测试账号信息，**绝不能部署这套本地 QA 脚本到公网**。

USB 连接手机后可运行：

```bash
adb reverse tcp:3319 tcp:3319
```

手机须由用户本人解锁。在手机浏览器打开 `http://127.0.0.1:3319` 可先验证网页版全屏扫码。最终 App 将仅使用事先信任的 HTTPS Lite 域名并复用活动方账号认证，不会读取花工木棉宿舍水电的校园会话。

## 安全边界与部署要求

当前已有独立原型数据库表 `events`、`staff_accounts`、`staff_sessions`、`registrations`、`audit`，所有学生个人资料仅与匿名报名 ID 关联。密码不记录明文；Cookie 是 HTTP-only；所有业务权限在 Worker 每次查询时检查，旧 `X-Lite-Staff` 私密链接**不再拥有授权能力**。管理员后台权限页面只是 UI，服务端独立二次限制。

`wrangler.example.jsonc` 默认 `LITE_ENABLED=false` 和 `SYNTHETIC_ONLY=true`，部署前要分配**全新的** D1/R2/Rate Limit Namespace，不得使用现有活动或社团招新数据库；`LITE_ROOT_TOKEN` 必须以 Wrangler secret 注入且不可存入代码。建议限制管理员口令重试、实现密钥遗失恢复流程、确定材料保存/清理政策、设置审核人员独立账号及真实活动试点的权限边界。

**项目目前尚未部署 Cloudflare，也未把 Android Beta 正式活动入口切换到 Lite。** 没有测试或收集真实学生资料。由于原型还未部署，`migrations/0001_init.sql` 是**新 Lite 环境的干净初始化结构**，不是可直接施加于任何已有业务库的升级脚本。
